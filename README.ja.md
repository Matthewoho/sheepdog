# sheepdog 🐕🐑

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

sheepdog は、オーナー自身のマシンで動く仕事用アシスタントです。1 分ごとに Lark（Feishu）から新着メッセージを取り込み、担当の AI セッションに渡し、各セッションの状態を管理します。オーナーの判断が必要なことは、セッションがボット経由で Lark 上のオーナーに聞きます。

名前の由来：オーナーが羊飼い、AI セッションが羊の群れ、sheepdog が群れをまとめる牧羊犬です。

## 群れボード

`sheepdog board` は、各セッションがいま何をしているかを一覧にします。セッションごとに実行状態、抱えている仕事、直近の操作を表示します。状態が変わると、バスセッションに要約が届きます。

- 実行状態は 6 種類：作業中、返信待ち、中断、連絡途絶、オーナー使用中、アイドル。sheepdog は毎ラウンド、配信台帳、セッションの記録、オーナー自身の入力記録から計算し直します。「返信待ち」はセッションの直近のレシートも参照します。
- 抱えている仕事は、主に sheepdog 自身が記録している事実から来ます：登録された返信待ち、未回答のオーナーへの質問、引き継ぎ、承認番号・PR・Linear 番号を含むメッセージが直近どのセッションに届いたか。セッションも `sheepdog work set` で自分で登録できますが、表示するだけで配信や状態は変えません。セッションがアイドルのまま 4 時間更新がなければ「古い可能性あり」と表示します。差分テストでは同じランダムなシナリオを、誤った登録と登録なしの 2 通りで走らせ、配信・通知・状態が完全に一致することを確認しています。
- 中断と連絡途絶：仕事を抱えたまま 15 分間新しいツール呼び出しがなければ中断、30 分間記録に変化がなければ連絡途絶と判定します。そのセッション宛ての新着メッセージは保留し、オーナーに DM します。セッションが動き出したら保留分を一度だけ配信し、復旧したことをオーナーに伝えます。
- オーナー使用中：オーナーがセッション内で入力してから 15 分間は配信せず、中断とも判定しません。
- 衝突の知らせ：メッセージ内の番号が直近ほかのセッションに届いていれば、どのセッションが担当していて今どういう状態かを添えます。知らせるだけで、配信先は変えません。
- セッション間のメッセージ：`sheepdog tell`。ヘッダーはコードで固定され、オーナーの指示ではないと明記します。同じ組み合わせで 10 分間に 6 件を超えると、その組を一時停止します。

## 処理の流れ

1. 取り込み：1 分ごとに lark-cli でオーナーとして新着メッセージを取得し、ローカルの台帳（SQLite）に記録します。
2. 振り分け：名簿とルールで渡すセッションを決めるか、受信箱に置きます。
3. セキュリティチェック：ルールに当たったものに印を付けるか、止めます。
4. 配信：セッションに送り、受領報告（レシート）を待ちます。
5. 相談：判断に迷うと、セッションがボットで Lark 上のオーナーに DM します。
6. 回答：オーナーが Lark で引用返信すると、答えは質問したセッションに戻ります。

```
Lark（lark-cli、オーナーとして）
   └─► 取り込み ──► 台帳（SQLite）──► ルーター ──► セキュリティチェック
                                                     ├─ 破棄
                                                     ├─ 受信箱（チャットごと）
                                                     └─ 配信 ──► セッション（Antigravity / Codex / Claude）
                                                          ▲                │
                                                          └── レシート ◄───┘
```

## 振り分け

| メッセージ | 行き先 |
|---|---|
| DM、@オーナー、@all、オーナーへの返信、重要人物の発言、キーワード一致 | そのチャットを担当するセッション。担当がなければバス |
| その他のグループメッセージ | 受信箱（チャットごと）。@オーナー や @all を含むバッチには受信箱の要約が付く |
| 通知オフのチャット（@オーナー なし）、オーナー自身のメッセージ | 送らない |

- 名簿（`roster.toml`）に、どのセッションがどのチャットを担当するかを書きます。`managed` のセッションには配信し、`known` のセッションはバスに担当範囲を知らせるだけで配信しません。
- バスは特別なセッションです。担当のないメッセージをすべて受け取り、名簿全体を知っています。バスは振り分けや転送などの軽い仕事だけを行い、具体的な作業は `sheepdog forward` で専任セッションに渡します。合うセッションがなければ `sheepdog new-session` で新しく開きます（既定で 1 日 5 件まで）。
- 通知オフのチャットは送りませんが、オーナーへの返信は届けます。
- オーナーが「判断してほしい」メッセージに引用返信すると、答えはそれを送ったセッションに戻ります。送り元が分からない場合は、原文を付けてバスに渡します。
- オーナーが既読のメッセージも「✓既読」付きで届けます。配信済みのメッセージが編集・取り消しされると、セッションに知らせます。

## セッション管理

- 各バッチにはバッチ ID が付きます。セッションは処理後にレシート（`handled`、`needs_decision`、`waiting_external`、`done`）を返し、それでセッションの状態が決まります：処理済み、オーナー待ち、相手待ち、終了。
- 判断に迷うと、セッションは `sheepdog ask` でボットからオーナーに DM します（報告は `sheepdog report`）。1 通に質問は 1 つ。1 行目は sheepdog が付け、セッションの topic ID（`[tp_xxx]`）を入れます。オーナーの返信はこれを頼りに戻ります。同じ件は同じ `--key` を付けると、最初の 1 通がメインのチャットに、以降はそのスレッドに入り、オーナーのスレッド内の返信はスレッドごとにセッションへ戻ります。
- 相手の返事を待つときは `sheepdog watch` で登録します。既定では 15 分と 30 分でリマインドし、60 分で返事がなければオーナーに報告します。返事が来ても、セッションが「待っていた答えだ」と確認するまでは待ち続けます。
- 引き継ぎ：退役するセッションは引き継ぎを書き、後任は前任の記録を最後まで読んでから始め、読んだ範囲をレシートに書きます。
- ルールを変えると、動いているセッションには次のバッチで新しいルール全文が届きます。

### セッションのホスト

各セッションは 1 つのホストで動きます。名簿と `new-session` で、セッションごとにホスト、モデル、推論レベルを指定できます。既存のセッションのホストは変えません。変えたいときは退役させて新しく開きます。

- **Antigravity**（既定）：Antigravity アプリ内蔵の `agentapi` でセッションを作り、メッセージを送ります。
- **Codex**：sheepdog が自分で `codex app-server` を起動し、1 ターンごとにバックグラウンドのプロセスで動かします。既定のモデルと推論レベルは `[hosts.codex]` で決め、セッションごとに変えられます。
  - 権限は Codex のプロファイルから来ます。`profile` を設定すると、sheepdog はそのプロファイルを読んで `-c` 引数に展開し、自分で起動した app-server に渡します。オーナーが Codex アプリで使っているセッションには触れません。それ以外のサンドボックスや承認の引数は付けず、Codex からの承認リクエストはすべて断ります。
  - プロファイルの変更は、その後に開いたセッションにだけ効きます。既存のセッションに反映するには、退役させて新しく開きます。
  - オーナーが Codex アプリでスレッドを開いている間は、アプリが書き込みロックを持つので、そのセッション宛てのバッチは待ち行列に入ります。60 分続くと、ボットがオーナーにアプリを閉じるよう知らせます。
- **Claude**：`claude -p` で動きます。コードはありますが、実環境ではまだ検証していません。
- Codex と Claude は既定でオフです。この 2 つでセッションを新しく開くにはオーナーの発言が必要です。`new-session --host codex|claude` には `--quote` が必須で、sheepdog がオーナー本人の言葉だと確認できたときだけ通します（`ask_owner_before_new`、既定でオン）。
- Codex と Claude のセッションはたいてい sheepdog の状態ディレクトリに書けないため、レシートのコマンドの代わりに、回答の最後に `sheepdog-receipt` ブロックを付けます。

## セキュリティ

- オーナーの指示として扱うのは次の 3 つだけです：
  - オーナーがセッション（Antigravity、Codex、Claude）に直接書いたこと；
  - バスが伝え、台帳と照合してオーナーの発言だと確認できた引用；
  - 送信者がオーナー本人のアカウントだと確認できた Lark の返信。
- Lark 上のほかの人の発言は情報として扱い、指示とはみなしません。
- セキュリティルールは `security.toml` に書きます。各ルールは正規表現と条件（外部の人か、送信者の種類）でできています。コードにキーワードは埋め込んでいません。
  - `tag`：通常どおり届け、本文の前に警告を付けます。サンプルのルールは、秘密情報、権限、削除、コードの実行、なりすましを対象にしています。
  - `hold`：バスにだけ届けます。バスがほかのセッションに渡すには、確認済みのオーナーの発言が必要です。サンプルのルールは、外部の人による秘密情報の要求、支払い、プロンプトインジェクションを対象にしています。
- 社内と社外の送信者はテナント（`own_tenant_keys`）で区別します。

## ガードレール

ホストがセッションのコンテキストを圧縮すると、最初に渡したルールが抜け落ちることがあります。sheepdog は毎ラウンド各セッションの記録を差分で読み、3 つのガードレールを足しています。

- **圧縮後のルール再送**：新しい圧縮点を見つけると、次のバッチに現行ルールの全文を付け、その前に再送の理由を 1 行添えます（`rules_after_compaction.md`）。Antigravity のセッションがまだ終わっていないバッチを抱えているときは、次のバッチを待たずにその場で全文を単独で送ります（バッチ扱いではなく、受領報告はそのまま）。Antigravity と Codex の圧縮点を認識します。Claude の書式は未確認です。
- **バッチごとの念押し**：playbook に `reminders/<key>.md` があるセッションには、毎バッチの最後にそのファイルを付けます。
- **危険なコマンドの監査**（`[audit]`）：監査対象のセッションが新しく実行したコマンドを `danger_patterns` と正規表現で照合します。当たったら：
  1. ボットでオーナーに DM します：どのセッションが、何時に、何のコマンドを（機密の値は伏せます）；
  2. 実行したセッションに通知を送ります（`audit_offender.md`）；
  3. `also_notify` のセッションに、繰り返す前に現状を確認するよう知らせます（`audit_notify.md`）。

  `ignore_patterns` にも当たるものは報告しません。たとえばヘルプの表示、`--dry-run`、メッセージ本文でコマンド名に触れただけのもの。10 分以内に報告済みの同じコマンドは繰り返し報告しません。まだ報告していないコマンドはすぐに報告し、そのたびにセッションへ停止の指示を送ります。オーナーへの個別メッセージが送れない場合（Lark のレート制限など）は間隔を空けて再送し、2 時間たっても送れなければ `sheepdog doctor` と `sheepdog board` の先頭に警告を出します。`sheepdog notices` で確認できます。これは事後の警告で、コマンドはすでに実行されています。

## オーナーとしての発言

- セッションがオーナーとして送るメッセージはすべてカードで、右下に小さな灰色の `[🐕Sheepdog Reply]` が付きます。相手は AI が送ったものだと分かります。返信は `sheepdog reply` で送ります。送る前に、そのチャットでオーナーがすでに発言していないかを読み取りだけで確認し、発言があれば送らずにオーナーの言葉をセッションに返します。
- `[ack]` を設定した場合：DM と @オーナー のメッセージがセッションに届くと、オーナーとして「Get」のリアクションを付け、返信したら外します。@all のものは付けるだけで外しません。
- 返信するか、どう返信するかは playbook で決めます。ボットやエージェントからのメッセージにはラベルが 1 行付き、その文言は `agent_sender_label.md` から取ります。サンプルでは「丁寧に一度だけ返し、やり取りを続けない」としています。ファイルがなければ「🤖 来自机器人 / Agent」（ボット / エージェントから）とだけ付けます。
- ループ防止：同じチャットで 10 分以内に代理返信が 4 回を超え、相手がボットだった場合、そのチャットを 30 分止めます。その間のメッセージは受信箱にだけ入れ、バスに知らせます。`sheepdog loops --clear` で手動で解除できます。

## オーナー自身の動きを伝える

- `[owner_context]` をオンにすると、オーナーが Lark で自分で書いたこと、付けたリアクション、編集・取り消ししたメッセージを、背景として担当セッションに送ります。セッションはこれを見て、オーナーが返した件には重ねて返さず、食い違うときはオーナーに合わせます。
- 代理返信のカードには印があるので、セッション自身のメッセージをオーナーの発言と取り違えません。
- オーナーがあるセッションに書き込んでいる間、sheepdog はそのセッションへの配信を止め、書き込みが止まって 15 分後に追いつきます。オーナーが Codex アプリでスレッドを開いているときも同じく待ち行列に入れます。

## 信頼性

- 1 ラウンドで取り込みきれなかったら、取り込み位置は進めずに次のラウンドで取り直し、メッセージ ID で重複を除きます。ネットワークのエラーは間隔を空けて再試行します。
- 台帳に書いてから配信します。配信の途中でプロセスが落ちたら、再起動後にセッションの記録と照合します。届いていたものは再送しません。確認できないものは「不確定」として、人が確認したうえで `sheepdog redeliver` で再送します。
- 200 行を超える長いメッセージは切り詰め、残りの行数と `sheepdog show` で全文を読む方法を添えます。
- `config.toml`、名簿、セキュリティルールは毎ラウンド読み直し、playbook はプロンプトを組み立てるたびに読みます。`state_dir` と `sink` 以外は再起動なしで反映されます。
- 台帳は既定で 7 日間保持し、期限が来たら消します。終わっていないものは消しません。

## 設定と使い方

### 必要なもの

- Python 3.11 以上（標準ライブラリのみ）
- [`lark-cli`](https://github.com/larksuite/cli)（`npm install -g @larksuite/cli`）、オーナー本人のアカウントでログイン済み
- [Google Antigravity](https://antigravity.google) デスクトップアプリ。sheepdog はアプリ内蔵の `agentapi` でセッションを作り、メッセージを送ります。`agentapi` はアプリ自身のプロセスの中でしか使えないため、sheepdog は Antigravity のサイドカーとして動きます。
- 任意：Codex や Claude のセッションを使う場合（`[hosts.codex]`、`[hosts.claude]`）は、`codex` / `claude` CLI をインストールしてログインしておきます。

### インストールと試運転

```bash
uv tool install .            # または: pipx install .
mkdir -p ~/.config/sheepdog
cp examples/config.example.toml   ~/.config/sheepdog/config.toml    # self_open_id を設定
cp examples/roster.example.toml   ~/.config/sheepdog/roster.toml    # 既存のセッションを登録（任意）
cp examples/security.example.toml ~/.config/sheepdog/security.toml  # own_tenant_keys を設定し、ルールを調整
cp -r examples/playbook           ~/.config/sheepdog/playbook       # 自分の仕事のやり方に合わせて書き直す

sheepdog doctor              # 設定、名簿、ルール、playbook ファイル、各ホストを確認
sheepdog init --dry-run      # init が送るメッセージをすべて表示。何も書き込まない
sheepdog poll --dry-run      # 実際のメッセージを取得し、振り分け結果を表示。何も書き込まない
```

### 本番運用

Antigravity のサイドカーとして動かします：

```bash
mkdir -p ~/.gemini/config/sidecars/sheepdog
cp examples/sidecar.example.json ~/.gemini/config/sidecars/sheepdog/sidecar.json   # パスは絶対パスで
```

Antigravity の **Automations** パネルで **sheepdog** を有効にします。起動時に `sheepdog init`（何度実行しても同じ結果）、続いて `sheepdog run` が走ります。ログは `~/.gemini/antigravity/sidecar_data/sheepdog/logs/sidecar.log` です。

### よく使うコマンド

```bash
sheepdog sessions            # 全セッション：ホスト、役割、担当チャット、状態、関連プロジェクト
sheepdog board [--topic tp_x] # 群れボード：各セッションの状態、抱えている仕事、直近の操作
sheepdog inbox [--chat X]    # 受信箱のグループメッセージ
sheepdog escalations         # オーナーの判断待ちの質問
sheepdog watches             # 誰かの返事を待っているセッション
sheepdog security-log        # セキュリティチェックで印を付けた・止めたメッセージ
sheepdog acks [--open]       # オーナーとして付けた確認リアクションと、外したかどうか
sheepdog show --topic tp_x   # そのセッションの直近数ターンのやり取り
sheepdog push-rules          # 新着を待たずに、セッションへルール全文をすぐ送る
```

### 設定ファイル

| `~/.config/sheepdog/` のファイル | 中身 |
|---|---|
| `config.toml` | オーナーの ID、取り込み間隔、キーワード、代理返信の印、待ち時間、オーナーへの相談用チャット、セッションのホスト、コマンド監査 |
| `roster.toml` | どのセッションがどのチャットを担当するか、役割、与えた権限、ホストとモデル |
| `playbook/*.md` | 業務ルールとメッセージのテンプレート：バス、開始時の説明、引き継ぎ、リマインド、セキュリティ、ボットメッセージのラベル、バッチごとの念押し |
| `security.toml` | セキュリティルール：正規表現と条件、`tag` か `hold` |
| `prompts/overlay.md` | 任意。バスへの追加指示（オーナーのノートの書き方など） |

コードは仕組みだけを持ち、業務ルールはすべてこれらのファイルにあります。完全なリファレンス（現在は中国語のみ）：[docs/reference.zh-CN.md](docs/reference.zh-CN.md)。

### データの置き場所

| 層 | 場所 | リポジトリに含む |
|---|---|---|
| エンジンのコード | このリポジトリ | はい |
| 設定、名簿、playbook、ルール | `~/.config/sheepdog/` | いいえ |
| 実行時データ（台帳、受信箱、レシート） | `~/.local/state/sheepdog/`、`retention_days`（既定 7 日）を過ぎたら削除 | いいえ |
| 仕事の成果物 | 各セッションがオーナー自身のノートやタスク管理に書く | いいえ |

- AI セッションに送った内容は AI ホスト側に保存され、sheepdog の削除の対象外です。
- sheepdog は Lark に対して読み取り専用です。例外は 2 種類だけ：確認リアクションの付け外し（`[ack]`、設定しなければオフ）と、ボットからオーナーへの DM（Codex / Claude CLI のログイン切れ、Codex アプリが書き込みロックを 60 分保持、危険なコマンドの警告、セッションが attention で止まったときの通知と自動復旧の連絡）です。
- sheepdog 自身はオーナーのノートやタスク管理に書き込みません。
- コミット前のチェック（`scripts/check_private_data.py`）が、実在のチャット ID、ホームディレクトリのパス、認証情報を止めます。テストは合成データだけを使います。

### 開発

```bash
python3 -m unittest discover -s tests -v
```

## 限界

- オーナーへの相談と代理返信は sheepdog 経由ですが、それ以外のメッセージ送信とコマンド実行はセッション自身が行い、sheepdog はその実行経路にいません。代理返信の書式、オーナーへの相談、セキュリティルールはどれもプロンプトでの約束で、コードで強制はできません。最後の防衛線は、セッションのホスト自身のコマンド権限と、オーナーのクラウド権限です。
- セキュリティチェックは正規表現なので、言い回しを変えると漏れることがあります。コマンド監査は実行後の警告です。
- Antigravity アプリを閉じると sheepdog も止まります。アプリを開き直すと、止まったところから再開します。
- 編集・取り消しに気づけるのは、元のメッセージから数分以内だけです。
- 取り込み元は今のところ Lark だけです。Claude のホストは実環境で検証していません。
- 一人の日々の仕事に合わせて作っているため、サンプルのルールにはその人のやり方が出ています。使う前に自分のやり方に書き直してください。
