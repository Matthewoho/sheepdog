# sheepdog 🐕🐑

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

**sheepdog は、あなたのマシン上で動く仕事のアシスタントです。** あなたが羊飼い、AI エージェントのセッションが羊の群れ、sheepdog が牧羊犬として群れをまとめます。

最初の仕事は、仕事用チャット（現在は Lark / Feishu）を見張ることです。届いた依頼をそれぞれ担当のエージェントセッションに渡し、セッションの状態を管理し、あなたの判断が必要なことだけを持ち帰ります。あなたは観察・指示・決定を、エージェントは収集・仕分け・対応・下書きを担当します。

## なぜ作ったか

仕事の多くがチャット経由で来ると、依頼はばらばらに届きます。DM、@メンション、何十ものグループのスレッド。一つの AI チャットには収まりきらず、AI チャットを十数個開いても振り分ける人がいなければ同じことです。

sheepdog はその間を埋める層です。

- **仕事の流れごとに担当を一つ。** 人やプロジェクトごとに長く動き続けるセッションを持たせるので、文脈が毎回リセットされず積み上がります。
- **振り分けは任せる。** 新しいメッセージはルールで仕分けられ、担当セッションに届くか、受信箱に置かれます。
- **決めるのはあなた。** 日常的な対応や返信の下書きはセッションが行います。迷うことはあなたに確認し、危険な操作にはあなたの明示的な許可が必要です。

## できること

| 届いたメッセージ | 行き先 |
|---|---|
| DM、自分への @、@all、自分への返信、重要人物の発言、キーワード一致 | そのチャットを担当するセッションへ。担当がいなければ**バス**セッションへ |
| その他のグループメッセージ | チャットごとの**受信箱**へ。@メンションされたときに要約を添付 |
| ミュート中のチャット（@メンションを除く）、自分の発言 | 無視 |

振り分けに加えて：

- **名簿（roster）**：すでに使っているセッションを登録できます。`managed` には sheepdog がメッセージを送り、`known` はバスが存在を知るだけで送信はしません。古いセッションを引退させて新しいセッションに引き継ぐこともでき、後任は着手前に前任の会話記録をすべて読む決まりです。
- **バスセッション**：担当のいないメッセージを受け取り、名簿全体を把握して、適切なセッションに転送します。合うセッションがなければ新しく立ち上げます。
- **あなたの発言を背景として共有**：あなた自身がチャットで発言したこと（編集・取り消し・付けたリアクションも）は、担当セッションに背景として届きます。あなたとエージェントの話が食い違わないようにするためです。
- **迷ったら人に聞く**：セッションは bot 経由であなたに DM します。バスセッションで答えても、Lark 上で直接返信しても構いません。sheepdog は返信があなた本人のアカウントからであることを確認し、質問したセッションに戻します。
- **相手の返信待ち**：セッションが待機を登録すると（`sheepdog watch`）、返信はそのセッションに直接届きます。15 分・30 分でリマインド、60 分で打ち切ってあなたに報告します（時間は設定可能）。
- **プロジェクトとの紐付け**：依頼がどのプロジェクトのものかを確認して記録するので、情報が散らばりません。
- **代理返信の印**：エージェントがあなたに代わって送るメッセージには、`🐕 [Agent 代回]` のような印が先頭に付き、本人の発言と区別できます。
- **セキュリティゲート**：設定可能なルールで、怪しいメッセージにセッションへ届く前に警告を付けたり保留したりします。認証情報の要求、権限付与、破壊的操作や本番環境の操作、「上司がもう承認した」という主張、プロンプトインジェクションなどが対象です。

## 仕組み

```
Lark（lark-cli、あなたの身元で）
   └─► 収集 ──► 台帳（SQLite） ──► 振り分け ──► セキュリティゲート
                                                  ├─ 破棄
                                                  ├─ 受信箱（チャットごと）
                                                  └─ 配信 ──► 配信器 ──► Antigravity のセッション
                                                                ▲                 │
                                                                └──── 受領報告 ◄──┘（sheepdog receipt）
```

- セッションはひとまとまりの処理ごとに受領報告（`handled`、`needs_decision`、`waiting_external`、`done`）を返し、それがセッションごとの状態遷移を動かします。
- あなたがセッションで入力を始めると、sheepdog はそのセッションへの配信を止め、入力が止まって 15 分後にまとめて届けます。
- メッセージの取得元、セッションの置き場、保存先はインターフェースになっています。現在実装されているのは Lark、Google Antigravity、SQLite だけです。

**仕組みはコードに、ルールは設定に。** 代理返信の印、いつあなたに聞くか、引き継ぎ方、セキュリティルールなど、業務ルールはすべて `~/.config/sheepdog/` の Markdown か TOML です。playbook の編集は次の配信から、`config.toml`・名簿・セキュリティルールは毎回の取得時に読み直されます。再起動もコード変更も要りません（`state_dir` と `sink` の変更だけは再起動が必要です）。

## 必要なもの

- Python 3.11 以上（標準ライブラリのみ）
- [`lark-cli`](https://github.com/larksuite/cli)（`npm install -g @larksuite/cli`）。ユーザー本人の身元でログイン済みであること
- [Google Antigravity](https://antigravity.google) デスクトップアプリ。sheepdog はアプリ内蔵の `agentapi` でセッションを作成・送信します。`agentapi` はアプリ自身のプロセス内でしか使えないため、sheepdog は Antigravity のサイドカーとして動きます。

## クイックスタート

```bash
uv tool install .            # または: pipx install .
mkdir -p ~/.config/sheepdog
cp examples/config.example.toml   ~/.config/sheepdog/config.toml    # self_open_id を設定
cp examples/roster.example.toml   ~/.config/sheepdog/roster.toml    # 既存のセッション（任意）
cp examples/security.example.toml ~/.config/sheepdog/security.toml  # own_tenant_keys を設定、ルールを調整
cp -r examples/playbook           ~/.config/sheepdog/playbook       # ルールを自分の言葉で書き直す

sheepdog doctor              # 設定・名簿・ルール・playbook を確認
sheepdog init --dry-run      # init が送るメッセージをすべて表示（何も書き込まない）
sheepdog poll --dry-run      # 実メッセージを取得し、振り分け結果を表示（何も書き込まない）
```

本番は Antigravity のサイドカーとして動かします。

```bash
mkdir -p ~/.gemini/config/sidecars/sheepdog
cp examples/sidecar.example.json ~/.gemini/config/sidecars/sheepdog/sidecar.json   # パスは絶対パスで
```

Antigravity の **Automations** パネルで **sheepdog** を有効にしてください。起動時に `sheepdog init`（何度実行しても安全）、続いて `sheepdog run` が動きます。ログは `~/.gemini/antigravity/sidecar_data/sheepdog/logs/sidecar.log` です。

## よく使うコマンド

```bash
sheepdog sessions            # 全セッション：担当、チャット、状態、紐付いたプロジェクト
sheepdog inbox [--chat X]    # 受信箱のグループメッセージ
sheepdog escalations         # あなたの判断待ちの質問
sheepdog watches             # 返信待ちの一覧
sheepdog security-log        # セキュリティゲートで警告・保留されたメッセージ
sheepdog acks [--open]       # あなたの代わりに付けた確認リアクションと、外したかどうか
```

## 設定の概要

| `~/.config/sheepdog/` のファイル | 内容 |
|---|---|
| `config.toml` | あなたの ID、取得間隔、キーワード、代理返信の印、待機時間、確認用チャット |
| `roster.toml` | どのセッションがどのチャットを担当するか、その役割、あなたが与えた権限 |
| `playbook/*.md` | 業務ルールとメッセージのテンプレート（バス、着任説明、引き継ぎ、リマインド、セキュリティ） |
| `security.toml` | セキュリティゲートのルール：正規表現と条件、動作は `tag`（警告）か `hold`（保留） |
| `prompts/overlay.md` | 任意。自分の作業環境向けの追加指示 |

詳細なリファレンス（現在は中国語のみ）：[docs/reference.zh-CN.md](docs/reference.zh-CN.md)

## セキュリティモデルと限界

- **指示として扱うのはあなたの言葉だけ。** チャットのメッセージは情報であって命令ではありません。セッションが「あなた」として扱うのは次の三つだけです：Antigravity であなたが入力したこと、バスが中継し sheepdog があなた自身の発言と照合した引用、あなた本人のアカウントからと確認できた Lark の返信。
- `hold` されたメッセージは担当セッションには届かずバスに行きます。照合済みのあなたの引用がない限り、バスから先へは出ません。
- **限界**：正規表現ではすべての言い換えを防げません。sheepdog は実行経路の上にいません。メッセージ送信もコマンド実行もセッション自身が行うため、最終的な防御線は、セッションが `security.md` に従うこと、Antigravity のコマンド権限、そしてクラウド側の権限設定です。

## データとプライバシー

| 層 | 場所 | リポジトリに含むか |
|---|---|---|
| エンジンのコード | このリポジトリ | はい |
| あなたの設定・名簿・playbook・ルール | `~/.config/sheepdog/` | いいえ |
| 実行時データ（台帳、受信箱、受領報告） | `~/.local/state/sheepdog/`、`retention_days`（既定 7 日）を過ぎたら削除 | いいえ |
| 仕事の成果物 | 各セッションがあなた自身のノートやタスク管理に書き込む | いいえ |

削除の対象はメッセージ、配信記録、判断待ちの質問、bot メッセージの出所、リアクション、終わった待機と動作、ループ記録、受領報告ファイルです。まだ終わっていないもの・進行中のものは残します。AI セッションに送った内容は AI ホスト側が保存しており、sheepdog の削除対象外です。確認リアクションの追加と削除（`[ack]`、設定しなければ無効）を除き、sheepdog はチャットに対して読み取り専用です。sheepdog 自体はあなたのノートやタスク管理に書き込みません。コミット前のチェック（`scripts/check_private_data.py`）が、実際のチャット ID、ホームディレクトリのパス、認証情報の混入を止めます。テストは合成データのみを使います。
