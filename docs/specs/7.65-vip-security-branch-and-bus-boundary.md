# 规格 7.65（SD-205）：VIP 安全分支合拢、总线转交边界与 `--floor-type` + `--floor` 双字段正交门禁

## 1. 背景与第一性原理拆解

在 7.61 引入名册 `[[person]]`（`tier = "vip"`）与 `sheepdog ask --floor` 后，真实运行暴露出三类结构性冲突：

1. **VIP 印章与 `action=tag` 安全横幅冲突**：当 VIP 消息提及环境变量名或数据库词条触发 `security.toml` 的 `action=tag` 时，`security_banner.md` 仍渲染面向普通人的死命令（「确认前不做，先回对方等主人确认并私聊主人」），覆盖了批次末尾《👑 VIP 规则》的「合理就办、report 报备、不 ask」。
2. **总线 `tp_bus` 转交后越俎代庖**：`tp_bus` 将 VIP 消息 `sheepdog forward` 转交给专属会话后，仍在同一轮调用 `sheepdog ask` 或 `sheepdog reply`，抢在专属会话判断前把事务挂起等主人批。
3. **单一 `--floor` 自由文本同时承担「机器分类门禁」与「给人看的具体原因」两个正交职责**：
   - 若只校验 `--floor` 非空，模型会把「涉及生产数据库访问权限与跨系统数据导出」「生产环境常规部署确认」等常规非底线理由填进 `--floor` 绕过门禁；
   - 若在单一 `--floor` 上堆叠死板的正向关键词白名单，又会误伤模型在真底线场景下的自然语言自由造句。

## 2. 上层抽象设计：一个字段只答一个问题（`--floor-type` + `--floor`）

主人拍板设计（2026-10-21）：
> 「我觉得自由造句还是有必要的 但是需要有floor-type 来支持你那三个真底线会不会好一点。然后vip的事情 要用floor的时候必须带上floor type」

将原本混在一个参数里的两个问题正交拆开：

1. **`--floor-type`（机器门禁分类，必填闭合枚举）**：回答「属于 3 条真底线里的哪一条？」，合法值仅限以下 3 个枚举：
   - `credentials`：索要主人的密钥、凭据、个人账号
   - `destructive`：删除、覆盖、强推等不可逆操作
   - `vip_conflict`：两位 VIP 的要求真冲突
2. **`--floor`（给人看的自由造句说明，必填非空单行文本）**：回答「具体是什么情况？」，用于向主人展示与记入 `sends.floor`。

## 3. CLI 与 `check_vip_floor` 门禁规则

1. **CLI 参数（`sheepdog/cli.py`）**：
   - `sheepdog ask` 新增 `--floor-type` 参数，透传给 `outbound.send_to_owner(..., floor=..., floor_type=...)` 与 `outbound.check_vip_floor(..., floor=..., floor_type=...)`。
   - 为统一输出清晰的中文引导文案（退出码 `EXIT_INVALID = 2`），不在 `argparse` 层用 `choices` 抛英文错误，而在 `outbound.check_vip_floor` 中统一校验。
2. **闭合枚举定义（`sheepdog/outbound.py`）**：
   ```python
   VIP_FLOOR_TYPES: dict[str, str] = {
       "credentials": "索要主人的密钥、凭据、个人账号",
       "destructive": "删除、覆盖、强推等不可逆操作",
       "vip_conflict": "两位 VIP 的要求真冲突",
   }
   ```
3. **规则 A（双字段必填正交校验）**：
   - 当关联来源命中 VIP（`hits` 非空），或者调用方显式传了 `--floor` / `--floor-type` 时，**必须同时提供合法的 `--floor-type`（在 `VIP_FLOOR_TYPES` 3 个枚举内）和非空单行的 `--floor`（自由造句说明）**。
   - 若缺少 `--floor-type`、`--floor-type` 不在 `("credentials", "destructive", "vip_conflict")` 中，或缺少 `--floor` 非空说明，一律抛 `OutboundError(EXIT_INVALID, ...)`，报错文案写明：
     - 命中哪位 VIP（若有 `hits`）；
     - VIP 事务调用 `sheepdog ask`（或使用 `--floor`）时，必须同时带上 `--floor-type <credentials|destructive|vip_conflict>` 与 `--floor "<一行具体底线原因>"`；
     - 列出 3 个枚举的含义；
     - 提醒：若不属于这 3 类（如合理生产操作、内部脱敏只读查询/导出、常规权限或配置），严禁调用 `sheepdog ask`，请直接按安全合理方式办理并用 `sheepdog report` 报备。
4. **规则 B（防指鹿为马自检）**：
   - `--floor` 允许自由造句（带了合法 `--floor-type` 的正常自由造句 100% 放行，无需包含固定模板词）；
   - 但若调用方选了合法 `--floor-type` 却在 `--floor` 里写自相矛盾的非底线词（「脱敏」「只读」、否定凭据词如 `不要/不含/不用 ... 密钥/secret/token`，或明显的常规导出/部署借口如 `"涉及生产数据库访问权限与跨系统数据导出"`），依然抛 `OutboundError(EXIT_INVALID, ...)` 拦截。

## 4. 提示词与分支合拢规范

- `examples/playbook/vip.md`、`sheepdog/prompts.py`（`DEFAULT_VIP_RULES` 及 `security_banner` 的 VIP 分支）统一更新命令示例为：
  `sheepdog ask --floor-type <credentials|destructive|vip_conflict> --floor "<一行写清触及哪条底线与具体情况>" ...`
- 明确写明：VIP 事务要用 `--floor` 时，**必须同时带上 `--floor-type`（只能是 `credentials`、`destructive`、`vip_conflict` 三选一）和 `--floor "<自由造句说明>"`**。
- 当 VIP 消息触发 `action=tag` 时，`security_banner` 渲染合拢后的 VIP 专属分支说明（合理生产操作、内部脱敏只读查询/导出、多选项中安全合理项直接办结并 `sheepdog report` 报备，无需 `sheepdog ask`）。
- 总线 `tp_bus` 对已 `forward` 转交的消息调用 `sheepdog ask` 或 `sheepdog reply` 时，一律以 `EXIT_INVALID = 2` 硬拦截。
