# 规格 7.67：消息入账即点确认表情、私聊点名 `sheepdog` 插话直达与羊圈副会话干净合成（SD-206）

## 1. 四步思考（从这一个到这一类）

1. **从这一个到这一类**：
   - 当专属会话（如 `tp_laohu`）正在跑长批次（`state = running`）时，新来的消息被队头阻塞（Head-of-Line Blocking）：① 对方看不到 `[Get]` 确认表情，以为消息石沉大海；② 主人在别人的私聊里直接文字点名 `sheepdog` 催问进展（私聊里无法 `@机器人`），被当成普通背景 `owner_context` 一并卡在队列里，无法触发 `owner_priority` 插话直达；③ 单槽位专属会话长活阻塞期间，该聊天的后续请求无空闲副槽位分流。
2. **找它从哪来**：
   - 确认表情（7.9）把「入账归属」与「送进模型上下文」绑死：只在 `Dispatcher._complete_delivery` 投递后点表情，一旦会话 `running` 排队，确认信号就被推迟。
   - 主人指令识别（7.45 A 类）只看群聊里的 `@机器人` mention 实体；私聊没有机器人，主人手敲 `sheepdog ...` 落入 `Collector._owner_context`（`reason = 'owner_context'`），而 `Dispatcher._priority_rows` 只放行 `owner_reply`、`owner_instruction` 和改口撤回，导致主人在私聊点名助理的话被挡在 `running` 门外。
   - `Roster.by_key` 在按 `max_sessions > 1` 合成 `#2..#N` 副会话时直接 `replace(base, ...)`，未清空主槽位一次性的 `predecessor_conversation_id` / `self_polling`；且 `Store.find_recent_thread_topic_in_group` 未对同一发送人在窗口期内已挂在 `active` 槽位上的 `pending` 消息做聚拢，导致连发多条无引用消息被拆散。
3. **让这一类不存在**：
   - **入账即点表情（幂等不重）**：`Collector` 在消息入账、完成安全闸（非 `hold`）且确定 `route = 'dispatch'` 与 `topic_id` 时当场调用 `_ack_ingested`；`acks` 主键表天然保证投递阶段 `Dispatcher` 兜底调用时不重复点第二次。
   - **点名 `sheepdog` 升格指令直达**：`Collector._owner_context` 用纯正则（剥离围栏代码块、行内代码、排除路径/文件名与代回前缀后匹配独立词 `sheepdog`）识别主人点名，直接走 `store.route_owner_instruction`（打 `owner_instruction` 与 `owner_at:mention` 标签）、记入回音账本并当场点 `bot` 确认表情；会话处于 `running` 时由 `Dispatcher._dispatch_priority` 秒级插话直达。
   - **羊圈副会话干净合成与连发聚拢**：`Roster.by_key` 合成 `#2..#N` 时显式清空 `predecessor_conversation_id`、`retire_predecessor`、`self_polling`、`retire_self_polling`；`Store.find_recent_thread_topic_in_group` 增加同 `chat_id` + `sender_id` 在 `active` 会话上有 `pending` 消息时的亲和聚拢；线上 `laohu` 开启 `max_sessions = 2`。
4. **眼前这一个**：
   - 修复 `tp_laohu` 在长批次执行期间老胡私聊消息与主人 `sheepdog 你看下为什么半天没动静` 排队无响应问题。

## 2. 结构改动清单

1. **`sheepdog/engine.py`**：
   - 新增 `OWNER_MENTION_TAG = "owner_at:mention"`、`_FENCED_CODE_RE`、`_INLINE_CODE_RE`、`_SHEEPDOG_CALL_RE` 及 `_has_owner_instruction_tag` / `_is_pure_owner_context`。
   - `Collector._ack_ingested(message_id)`：在 `ingest` 各 `DISPATCH` 分支及 `_handle_change` 升格 `DISPATCH` 分支（均在 `self._secure` 之后）当场点确认表情。
   - `Collector._owner_sheepdog_call(m)` 与 `Collector._owner_context(m)`：主人在非找主人聊天点名 `sheepdog` 时升格为 `owner_instruction`，兜底无归属时投 `tp_bus`，登记 `owner_echoes` 并点确认表情。
   - `Dispatcher._dispatch_topic` / `_priority_rows` / `_found_delivered`：按 `_is_pure_owner_context` 区分纯背景与指令，支持 `owner_instruction` 标签插话直达。
2. **`sheepdog/prompts.py`**：
   - `_fmt_msg` 中 `instruction = OWNER_INSTRUCTION_TAG in tags or row["reason"] == "owner_instruction"`，且 `if row["reason"] == "owner_context" and not instruction:` 才渲染 `OWNER_CONTEXT_LABEL`。
3. **`sheepdog/roster.py`**：
   - `Roster.by_key` 合成 `#2..#N` 副会话时清空 `predecessor_conversation_id`、`retire_predecessor`、`self_polling`、`retire_self_polling`。
4. **`sheepdog/store.py`**：
   - `find_recent_thread_topic_in_group` 新增同一 `chat_id` + `sender_id` 在窗口期内已有 `pending` 消息挂在组内 `active` 会话时的聚拢查询。
